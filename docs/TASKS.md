## План поэтапных функциональных проверок

Живые проверки по слоям — от дешёвых к дорогим; каждый этап даёт «GO/NO-GO» для следующего.
Автотесты (этап 0) обязательны перед любым живым прогоном; живые этапы — после изменения
кода/конфига и после перезапуска бота.

### Этап 0 — статический (автоматически, без токена)
1. `make` и `make NO_PYTHON=1` — чистые `-Wall` (кроме `-Wno-attributes` на py.cpp).
2. `ctest --test-dir build` (units + pytest) и `ctest --test-dir build-nopy` (units).
3. Smoke без токена: пустой `config.json` → `FATAL: Vk: не задан token...`, код 1.

### Этап 1 — запуск и longpoll (боеспособность)
1. Боевой `config.json` (ключ сообщества) → старт без падения; допустим warning про `user_token`.
2. В логе нет `CURL ERROR`/`Lp:`-предупреждений; `ss -tnp | grep vkbot` — есть ESTAB-соединение с VK.
3. Простой 10–15 мин (или между прогонами) — лог молчит, соединение живое, ts не отстаёт.

### Этап 2 — базовые сообщения и справка
1. `/help` — текст «твой уровень прав…», клавиатура разделов (пустых рядов нет).
2. `/всекоманды` — список по разделам `[ категория ]`; для обычного юзера `/py`/`/set` скрыты.
3. Ярлыки `/игры`, `/утилиты`, `/все` — отвечают как соответствующие кнопки.

### Этап 3 — кнопки (callback)
1. Нажатие кнопок в `/help` — разделы меняются, «некорректный ответ» клиент не показывает (`event_data`).
2. `/bc` старт → цифры жмутся кнопками, ответ бота корректен (проверка 911 на payload/ряды).

### Этап 4 — python-слой
1. `/py print("тест")` — отдельное сообщение + финальный ответ без дублирующего «done!».
2. `/py for i in range(5): print(i)` — но это одна строка с `;`, реальный пример: `/py import vkcppbot; print(vkcppbot.str.low(eventIn.msg))`.
3. `/py 1/0` — traceback текстом, бот жив.
4. `/pywiki` — 7 разделов ~по одному в секунду.
5. Флуд-контроль: много print'ов → обрыв «вывод обрезан» (или временно уменьшить `py_print_max_msgs`).

### Этап 5 — медиа
1. `/pix текст` — картинка-вложение доставлена.
2. `/vox 1` (нужны wav из субмодуля vox) — аудиосообщение.
3. `/apod` — фото дня; `/crt`, `/w` по вкусу.

### Этап 6 — игры
1. `/g` в личке и в беседе: создание, вход, ходы, «не твой ход», stop.
2. Полный цикл `/bc` кнопками (пересечение с этапом 3).

### Этап 7 — админ (владелец acess 5)
1. `/stat` — аптайм/счётчики; `/set` — клавиатура уровней, `/set <user> N` применяется.
2. `/con ls` — вывод команды; `/u` — загрузка файла; `/setc` — правка конфига + сохранение.

### Этап 8 — отказоустойчивость (по возможности)
1. Обрыв/нестабильная сеть: в логе ретраи Net (`wait internet connection...`), после восстановления
   события снова обрабатываются (не требуется рестарт).
2. Долгий простой (>15 мин): первое сообщение после простоя обрабатывается (ключ longpoll
   обновляется по `failed`).
3. Битый JSON от LP-сервера не роняет процесс (в автотестах закрыто try/catch-логикой;
   в жизни — отсутствие падений в логе).
