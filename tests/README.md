# Что проверяют автотесты

Два исполняемых файла (регистрация в `CMakeLists.txt`, запуск — `make test` / `ctest`):

- **`vkbot_unit`** (`tests/units.cpp`) — C++-слой: сеть, парсинг событий VK, команды,
  клавиатуры, игры, файлы, строки, поток выполнения. Строится и в `NO_PYTHON`.
- **`vkbot_pytest`** (`tests/py_integration.cpp`) — python-слой через настоящий `pyF`
  (под-интерпретатор pybind11). Только со сборкой с Python.

Общие принципы:

- **Без сети и токенов.** Сеть подменяется моком `FakeNet` (`tests/fakenet.h`): он пишет
  все вызовы (`url` + `params`) и отвечает настраиваемым JSON по подстроке URL. Команды
  прогоняются полным конвейером (`Worker::work → cmd::start → Event::send → Vk → FakeNet`).
- **Герметичность.** В начале `main` глобальные `conf`/`bd` сбрасываются в пустые объекты;
  тестовые файлы (`test_conf.json`, `test_dat.json`, временные) удаляются в конце.
  Повторные прогоны не зависят от предыдущих.
- Исключения сети/скриптов в тестах — ожидаемое поведение, процесс должен оставаться жив.

## vkbot_unit — C++-слой

### U1 — Net ограничивает повторы
`Net::send` на несуществующий хост (`.invalid`) возвращает пустой ответ, и повтор заканчивается
за конечное число попыток (`netRetries`). Закрывает историческую бесконечную рекурсию
`send→send` при сетевой ошибке.

### U2 — urlEncode
Кодирование параметров: пробел → `%20`, `=`, кириллица → percent-encoding UTF-8.
Без этого ломаются все POST-запросы к VK.

### U3 — BD dirty-флаг (пакетное сохранение `dat.json`)
`saveIfDirty()` не пишет чистый файл, пишет после `touch()`, снова становится «чистым»
после записи; деструктор `BD` дописывает несохранённые изменения. Гарантирует, что команды
дёргают диск редко (пакет в `Lp::loop` раз в 30 с), а не на каждое событие.

### U4 — str::low без `<codecvt>` (C++17)
Понижение регистра: ASCII + кириллица + Ё→ё; чужие скрипты (греческий) — pass-through;
битые UTF-8 байты не роняют и не обрезают строку; пустая строка — пустая. Закрывает миграцию
с удалённого в C++17 `<codecvt>`.

### U5 — str::words / summ / replase
Разбор сообщения на слова (учёт ¯\_(ツ)_/¯ не нужен), склейка с номера (аргументы команды),
замена подстрок. Регулярка на регрессии в парсере команд.

### U6 — fs roundtrip
`writeData` → `readData` побайтово сохраняет UTF-8; `exists` различает существующий/несуществующий.

### U7 — эталонное сравнение `img::neonColors`
Векторная (SIMD-подобная) реализация «неон-фильтра» совпадает со старым попиксельным циклом
с точностью ±1 LSB на случайном шуме, и быстрее (бенчмарк 1280×720, минимум из 3 замеров —
одиночные прогоны под фоновой нагрузкой давали ложные падения). Численные оптимизации
не должны менять картинку.

### U8 — Keyboard: формат JSON-клавиатуры VK
Флаги `one_time`/`inline`; ряды кнопок; типы действий `callback` (с payload), `openlink`,
`text`; **пустые ряды вырезаются**; ряды длиннее 5 кнопок **автоматически переносятся**.
Закрывает живой API-ошибку 911 (пустой ряд / >5 кнопок в ряду).

### U9 — парсинг `message_event` (нажатие callback-кнопки)
`user_id/peer_id/event_id`; **payload = JSON `{"cmd": "..."}`** → команда в `msg` и `words`;
скалярный payload старых клавиатур тоже принимается; `is_chat` по peer. Закрывает живую
ошибку 911 (payload обязан быть JSON-строкой ≤255) и формат ответа.

### U10 — `Event::send` прикладывает keyboard
Клавиатура из `eventOut.keyboard` уходит параметром `keyboard` в `messages.send` (иначе
кнопочный UI не работает вовсе).

### U11 — полный конвейер `message_event`
FakeNet + `Worker::work`: нажатие кнопки отвечает `messages.sendMessageEventAnswer`
с параметром **`event_data`** (не `answer` — живая фикс), затем payload-команда выполняется
как обычная (`/rename` меняет имя в `bd`). Проверяет диспетчеризацию кнопок целиком.

### U12 — `/help`: справка, разделы, ярлыки
По сообщению `/help` — ответ «уровень прав…» + клавиатура разделов; текст про подгруппы
с количеством и текстовые ярлыки; `/help все` / `/всекоманды` — полный список по разделам
(`[ игры ]` и т.п.), недоступные по правам команды ( `/py`) скрыты; ярлык `/игры` равен
`/help игры`. Держит UX справки в рабочем состоянии.

### U13 — парсинг `message_new`: вложения, пересылки, беседа
Фото (выбор наибольшего размера), документ (`type_id_owner_key` в `get()`), `fwds`
(пересланное сообщение), `is_chat` для беседы.

### U14 — `wall_post_new` → комментарий к записи
`owner_id` сообщества **знаковый**: `peer_id == -1` (не 2^32-1 — иначе `wall.createComment`
уходит с невозможным `owner_id`), `post_id` в запросе.

### U15 — диспетчер `cmd::start`
Неизвестная команда → false; команда выше прав → false (не выполняется); доступная →
выполняется и формирует `msg` (`/stat` → «Работаю…»).

### U16 — users::getUser / changeUser
Новый пользователь создаётся через `users.get` (FakeNet) с `acess=1, msgs=0`; счётчик `msgs`
растёт при чтении и **не** растёт при `inc=false`; `changeUser` пишет изменения в `bd`.

### U17 — Doc get() вырожденных случаев
Пустой `Doc` и видео без `access_key`: `get()` возвращает корректную строку вида `video2_1`,
без исключений/мусора.

### U18 — движок игры /g
Стартовое состояние, ход, смена игрока, «не победил», рендер карты эмодзи
(`⭕`, `1⃣`). Чистая логика, без сети.

### U19 — `/bc` (быки и коровы) через кнопки
Полный цикл FakeNet+Worker: интро, клавиатура цифр (ряды 5+5+3), набор цифры
(«ввод: 1234 [4/4]»), отправка проверки ответа.

### U20 — `/w` погода
Без аргумента — кнопки городов и подсказка; `/w Москва` — разбор JSON ответа
openweathermap (мокируется) в текст сообщения.

### U21 — `/set` без аргументов
Для админа — клавиатура уровней доступа (права проверяются до генерации).

### U22 — игра `/g` в беседе (полный конвейер)
Создание, отказ играть с собой, вход второго игрока, ходы, «не твой ход», ход с координатой
+ смена хода, «кординату введи», `stop`. Самая большой сквозной тест игровой механики.

### U25 — `Net::setTimeout`
После `setTimeout(1)` запрос на «чёрную дыру» (неотвечающий адрес) возвращается пустым
за единицы секунд, а не висит 600 с. Закрывает живой регресс: longpoll молчал ~7 минут
на зависшем соединении (см. `docs/TASKS.md`).

### U26 — 64-битные id VK (живой регресс 2026)
`message_new` с `from_id/peer_id` нового формата (~2·10¹¹, диалоги с ботами): событие
обрабатывается, ответ уходит на `peer_id=200006334752`, пользователь заведён в `bd`.
До фикса int32 обрезал id в отрицательное число и бот молча терял все сообщения.

### U27 — ThreadPool (перенесён из субмодуля в проект)
`enqueue` возвращает корректные future-результаты (50 задач + функция с возвращаемым
значением); исключение задачи доезжает до `future.get()`; **post()**: исключение не убивает
поток пула (раньше — `terminate` процесса), растёт `failedTasks()`, пул продолжает
выполнять задачи.

### U28 — атомарная запись файлов состояния
`fs::safeWriteData`/`BD::save`: запись идёт во временный `.safe` и переименовывается —
процесс, убитый посреди сохранения, не оставляет битый `config.json`/`dat.json`. Живой случай
2026-10-24: прерванная запись/сбой превращали старт бота в FATAL.

### U29 — `Vk::send` на неразбираемом ответе API
Ответ не JSON (сетевой сбой, «service unavailable») → предупреждение в лог и `null`,
без исключения. До фикса такой ответ вешал старт бота (FATAL в Lp-конструкторе).

### U30 — имена полей multipart-загрузки VK
Фото грузится в `photos.getMessagesUploadServer` полем **`photo`**, документы — в
`docs.getMessagesUploadServer` полем **`file`**. Живой случай 2026-10-24: `/neon` не отправлял
фото — VK отдавал `photo:""` и `saveMessagesPhoto` падал с ошибкой 100. Заодно мок вскрыл,
что `docs.save` возвращает doc без `url` — присваивание `url`/`link_mp3` теперь guarded.

### U31 — новый APOD и `str::htmlToText`
Живой случай 2026-10-24: `/apod` молчал — `api.nasa.gov` отдаёт с этого хоста HTML-403
(AWS ELB, до проверки ключа), а `json::parse` кидал исключение (WORK ERROR). Legacy-эндпоинт
NASA архивирует 01.12.2026, поэтому источник заменён на WordPress-эндпоинт
`science.nasa.gov/wp-json/wp/v2/apod-basic` (доступен, ключ не нужен). Проверки: `htmlToText`
(вырезание тегов, `&amp;`/`&#8217;`/числовые сущности, `<br>` -> перевод строки); `/apod` полным
конвейером — заголовок и очищенный explanation в сообщении, фото с `hdurl` приложен
(attachment `photo…`); не-JSON ответ -> вежливое сообщение вместо молчания.

### U32 — `/apoddate` и `/apodrand` (категория «космос»)
Полный конвейер через FakeNet: дата из текста (`01.10.2014` -> запрос `apod-basic/141001`);
дата из дня рождения профиля (`bdate` из `users.get`); ДР раньше 16.06.1995 -> сдвиг дня/месяца
на последний прошедший год (запрос всё равно уходит); скрытое ДР -> просьба ввести дату текстом;
несуществующая дата (`29.02.2014`) -> «такой даты не бывает» без запроса к NASA;
ранняя дата -> подсказка про начало эпохи APOD; `/apodrand` -> URL с 6-значной датой YYMMDD.

### U33 — стойкость к не-JSON ответу upload-сервера
Живой случай 2026-10-24: `/apodrand` промолчал — большая картинка со старого APOD не
загрузилась (upload-сервер ответил HTML), а строгий `json::parse` в `Doc::uploadPhoto`
бросил исключение (WORK ERROR вместо сообщения). Проверки: `uploadPhoto` возвращает false
без исключения; полный конвейер `/apodrand` при неудачной загрузке присылает сообщение
с описанием и ссылкой на пост вместо молчания.

### U34 — комментарий к записи стены как команда (`wall_reply_new`)
Комментарий от имени **другого сообщества** (`from_id` отрицательный) под тестовой записью —
полноценная команда: парсятся `cid` (id комментария), `id=post_id`, `peer_id=owner_id`;
`getOut()` переносит `cid`, чтобы ответ ушёл тем же `wall.createComment`, но с `reply_to_cid`
— в ветку команды, а не отдельным верхним комментарием. На сообщество `users.get` не зовётся
(метод не работает с отрицательными id) — в `dat.json` сразу создаётся запись `{acess:1, msgs:0,
name:""}`; пустое имя не печатается в префиксе ответа («, » без имени). Публичные команды
(/stat) выполняются, ответ содержит текст команды.

### U35 — защита от петли собственных комментариев
Комментарий, который сообщество оставило под собственной записью (`from_id == owner_id`),
не обрабатывается: longpoll отдаёт и собственные комментарии, и без фильтра ответ бота
вызвал бы новый `wall_reply_new` и цепочку ответов до бесконечности. Проверка: после
`w.work()` с таким событием ни одного вызова `wall.createComment`.

### U36 — самопроверка чекера (маркер «@@ »)
2026-10-24 VK закрыл group-токенам доступ к чужим стенам (`wall.createComment` в чужое
сообщество — ошибка 15, `wall.post` — 214), поэтому автоматический чекер `tools/live_check.py`
не может писать «от другой страницы» — у него остаётся токен самого сообщества. Исключение в
петле-фильтре U35: собственный комментарий обрабатывается, только если начинается с маркера
«@@ » (его ставит чекер в режиме `--self`). Ответы бота маркера не содержат — зацикливание
исключено. Проверки: «@@ /stat» выполняется и отвечает в ветку; маркер вырезан из команды
(в `words`/`msg` его нет).

### U37 — отрицательный `peer_id` при загрузке вложения
Для ответов под записью стены `peer_id` = отрицательный `owner_id` сообщества. Методы
загрузки (`uploadPhoto`/`uploadDoc`) принимали его беззнаковым, и VK возвращал ошибку 100
«peer_id not int64» (живой случай: `/apod*` под комментарием не могли приложить фото).
Проверка: в `photos.getMessagesUploadServer` уходит точная строка «-178228638».

### U38 — пустой ответ не отправляется
Команда без текста и вложений раньше отправляла пустой `messages.send`/`wall.createComment`
и ловила ошибку 100. `Event::send` теперь пропускает пустые ответы (включая случай, когда
отправляется только префикс имени «Имя, »).

### U39 — источник картинки для арт-команд
`/pix` `/crt` `/neon` берут изображение: 1) из вложений сообщения/комментария (фото или
документ; в `wall_reply_new` VK отдаёт вложение одиночным полем `attachment` без поля `type` —
тип выводится из ключа); 2) если вложений нет — фото профиля автора (`users.get`
`fields=photo_200/100/50`, для сообщества — `groups.getById`). Проверки: разбор одиночного
`attachment`; `/neon` без вложения загружает обработанное фото профиля (сквозной прогон
с мок-загрузкой); при отсутствии картинки комментарий не отправляется (U38); при сбое загрузки
фото (для стены это норма: group-токен не может грузить фото на стену — 901/27) бот отвечает
объяснением вместо молчания.

## vkbot_pytest — python-слой (`/py`)

Тесты гоняют настоящий `pyF` (pybind11, под-интерпретатор на скрипт) с `PyMainThread`
(GIL главного потока отпущен навсегда — без него создание под-интерпретатора из worker-потока
умирает в deadlock). Сеть — `FakeNet` там, где скрипт что-то шлёт.

### T1 — скрипт правит `eventOut.msg`, модуль `vkcppbot.str`
Базовый прогон: python-код меняет ответ, встроенный модуль строк работает из скрипта.

### T2 — runtime-исключение возвращает traceback
`1/0` → ошибка текстом, процесс жив, `pyF` переиспользуется.

### T3 — синтаксическая ошибка тоже возвращается текстом
Битый код не роняет интерпретатор-обёртку.

### T4 — изоляция под-интерпретаторов
Глобалы одного `/py` не видны следующему; состояние не течёт между запусками.

### T5 — `vkcppbot.fs`
Чтение/запись файлов из скрипта, кастеры str↔C++, UTF-8 проходит целиком.

### T6 — кастер `vector<string>` ↔ list
`str::words`/`summ` через python-списки в обе стороны.

### T7 — биндинг `Doc`
Свойства (`type/id/url/...`) и `get()` видны скрипту.

### T8 — `eventIn` в скрипте, read-only поля защищены
Чтение полей события; запись в защищённое поле → python-ошибка, а не UB.

### T9 — GIL/многопоточность (критический)
N потоков одновременно крутят свои `pyF`. Без `PyMainThread(gil_scoped_release)` это
deadlock — тест закрывает главный инвариант python-слоя.

### T10 — `Keyboard` из скрипта
Построение VK-клавиатуры (rows/buttons/payload) из python, `dump()` → валидный JSON.

### T11 — `print()` = отдельное сообщение
Два print → ровно два `messages.send` с правильным содержимым (тесты ставят
`py_print_interval_ms=0`, чтобы не ползти по секундам).

### T12 — `eventOut.msg` и `print` раздельны
msg отправляет вызывающий код (worker), print — свои сообщения; не склеиваются.

### T13 — print до исключения
Печать до ошибки уже ушла в чат, ошибка возвращается как раньше.

### T14 — лимит print-сообщений на скрипт
`py_print_max_msgs=3`: из 10 print'ов уходят 3 + уведомление «…обрезан…», дальше тишина.
Флуд-защита от бесконечных циклов с print.

### T15 — интервал между print-сообщениями
`py_print_interval_ms=300`: три сообщения суммарно не быстрее ~600 мс (троттлинг по времени).

### T16 — `/pywiki`
Текст вики (`pyWikiScript()`) исполняется как обычный скрипт: ≥5 сообщений, первое —
«Wiki /py …», ошибок нет. Держит справку по `/py` в рабочем состоянии.

## Куда добавлять новые проверки

Не отдельными скриптами, а в `tests/units.cpp` / `tests/py_integration.cpp` —
CTest-цели настраиваются в `CMakeLists.txt`; здесь (в README) добавляем описание нового
теста тем же форматом.
